# Documentation governance

Tale UI documentation is maintained as part of the product surface. Current
guidance must agree with the shipped packages, source code, generated
registries, CI workflows, and supported tooling.

## Sources of truth

When two sources disagree, use this order:

1. Public source code, types, tests, and package exports define behaviour.
2. Package manifests, workspace configuration, and GitHub workflows define
   package boundaries, commands, releases, and CI.
3. Canonical Markdown and MDX explain those facts for consumers and
   maintainers.
4. Generated registries, snippets, agent context, catalog tables, and unified
   artifacts project canonical sources into machine-readable or bundled forms.

Do not patch a generated file to conceal drift. Correct its canonical input or
generator, then regenerate it.

## Current and historical scopes

Current guidance includes the root and package READMEs, `CLAUDE.md`,
`CONTRIBUTING.md`, `SECURITY.md`, current files under `docs/`, and operational
guides under `test/` and `tools/`.

The following scopes record decisions or preserve released material and are not
rewritten merely to match the current tree:

- `analysis/` and `plans/`;
- `docs/plans/` and `docs/archive/`;
- `docs/versioned/v1/`; and
- package changelogs.

Historical documents should be clearly read as snapshots. Correct them only
when their own historical record, links, or safety guidance is wrong.

## Authoring rules

- Link to a canonical registry or workflow instead of copying volatile counts
  or inventories into prose.
- Use package names and repository paths that exist in the current workspace.
- Mark package lifecycle and release channels explicitly.
- Keep consumer guidance independent of a specific agent where possible.
  Agent-specific setup may be documented when it is an actual supported
  integration.
- Keep examples executable and aligned with public imports, props, tokens, and
  composition patterns.
- Add new current guidance to the semantic audit when its truth can be checked
  deterministically.

## Generated documentation

Run the complete generation pipeline after changing a component, component
doc, recipe, pitfall, A2UI catalog, capability manifest, or other canonical
artifact source:

```bash
pnpm generate-docs
pnpm generate-docs:check
```

The pipeline covers component and pitfall registries, consumer snippets,
Cursor rules, eval context, A2UI catalog outputs, unified artifacts, roadmap
contracts, governance reports, current-version documentation provenance,
metrics, Figma and native conformance outputs, hosted artifacts, and roadmap
evidence. Evidence generation runs last so it records the final derived
digests.

The slim and offline consumer snippets are both generated by
`tools/generate-consumer-snippet.js`. The install-time `tale-ui-setup` command
reads the packaged generated snippet rather than carrying a separate copy.

## Reconciliation checks

Run the semantic audit directly while editing prose:

```bash
pnpm audit:docs:semantics
```

It checks current tracked Markdown and MDX for broken relative links and known
stale repository identities, commands, paths, tokens, and inventory claims. It
also reconciles the root package inventory, supported security major, and
monorepo MCP tool documentation with their canonical sources.

Before merging documentation changes, run:

```bash
pnpm audit:docs:semantics
pnpm markdownlint
pnpm prettier
pnpm generate-docs:check
```

Use the focused test commands in [`test/README.md`](../test/README.md) when an
example, script, configuration file, or runtime integration changes.
